## 1.8.0 — 2026-08-24

### Changed

- 搜索框在有查询时将右侧 `Ctrl F` 提示原位切换为“清空搜索”按钮；鼠标或辅助技术用户无需先聚焦输入框即可返回全部条目，`Esc` 继续提供同一键盘动作。
- 补全搜索结果列表的键盘闭环：`Enter` 从当前结果进入正文，活动查询下 `Esc` 一步清空并返回搜索框，同时保留当前 Note 上下文。
- 将应用状态接入 WPF UI Automation live region：用户动作结果采用 `Polite`，可恢复错误采用 `Assertive`；普通自动保存过程保持静默，避免连续输入产生播报噪声。
- Note 结果列表改用数据项与 WPF 回收式 UI 虚拟化；大集合不再为每条 Note 预先创建完整控件树，选择、右键菜单、拖拽映射和辅助技术名称保持原行为。
- 搜索、视图、分类和内容版本未变化时复用同一只读筛选快照，避免选中校正与界面刷新对同一 5000 条集合重复筛选、排序和分配；分类范围在排序前先缩小候选集。
- 将纯 Note 选择从通用内容变化事件中分离：切换条目只同步列表选择、编辑器和文档状态，不再重扫导航/分类计数、刷新结果列表或重复刷新编辑器。
- 标题/正文输入的 120 ms 合并刷新只更新依赖文字的结果集合，不再重复扫描与文字无关的智能视图计数和分类计数；搜索匹配、更新时间排序、列表标题与正文预览保持即时一致。
- 将活跃、收藏、回收站和分类计数抽取为单遍只读 `NavigationSnapshot`；导航内容与选择均未变化时跳过控件写入，分类顺序或任一计数变化时仍完整更新。
- 由 `MainViewModel` 缓存当前导航快照并显式区分计数相关与无关变更；正文/标题、置顶小窗内容、搜索和纯选择不再为证明导航未变而扫描全部 Note，收藏、删除/恢复、移动和分类变更仍立即重建正确计数。
- 编辑器分类下拉复用导航快照的有序分类；Note 切换、搜索或仅计数变化时保留现有 `ComboBox` 项并只更新选择，分类创建、重命名、删除或重排时仍重建正确顺序。
- 自定义分类侧栏按可见容量自适应：0 个分类不创建不可见列表，1–6 个分类保留轻量直接行，第 7 个起改用 WPF 回收式 UI 虚拟化；100 个分类不再预建 100 棵视觉行，选择、计数、双向排序、右键菜单、Note 投放、分类投放、Tooltip 与辅助技术名称保持一致。
- Note 列表右键菜单同样按可见容量自适应：1–6 条保持直接菜单，第 7 条起复用活动/回收站命令树；两种路径都在打开时冻结精确 Note 身份，后续选择变化不会误收藏、误删除或误还原其他 Note，命令执行或关闭后不保留正文对象引用。
- 清空回收站改用 `List<T>.RemoveAll` 单次稳定压缩，避免逐条 `Remove` 反复搬移尾部元素和创建待删列表；原集合身份、保留项顺序、选择校正、缓存失效、保存状态及空操作不通知语义保持不变。

### Verified

- 六组自动化测试通过；真实窗口验证结果列表的 `Enter`/`Esc` 焦点行为，默认 `1080×686` 与最小 `860×506` 的真实 WPF 搜索激活态无文字覆盖、按钮裁切或三栏位移。
- 状态反馈测试覆盖动态 UIA 名称、`Polite`/`Assertive` 优先级和自动保存静默门控；实际 Narrator 语音输出留待人工辅助技术验收。
- 同机 3000 条首屏构造与布局中位数由约 `2522.9 ms` 降至 `32.4 ms`，约快 `98.7%`；自动化测试确认 3000 个数据项完整保留、首屏仅实现 7 个容器，滚动回收后 UIA 名称与菜单不串行。
- 同机 5000 条搜索变化后刷新中位数：全部范围由 `5.461 ms` 降至 `3.390 ms`（约快 `37.9%`），分类范围由 `5.106 ms` 降至 `0.794 ms`（约快 `84.4%`）；稳定筛选快照读取低于 `0.001 ms/次`。
- 同机真实 WPF 窗口在 5000 条列表中切换 Note 的中位数由 `1.496 ms` 降至 `0.153 ms`，约快 `89.8%`；展示测试确认标题、正文、选中对象与虚拟化数据源保持同步。
- 同机 5000 条真实文本输入与延迟刷新中位数由 `3.066 ms` 降至 `1.038 ms`，约快 `66.1%`；真实 160 ms Dispatcher 定时测试确认列表标题和正文预览仍更新。
- 同机 5000 条、100 分类的未变化导航刷新中位数由 `1.669 ms` 降至 `1.220 ms`，约快 `26.9%`；每次真实改变收藏计数时为 `1.562 ms`，仍比旧路径快约 `6.4%`。
- 同机 5000 条、100 分类的两次交错复跑中，专用失效缓存将稳定导航刷新由 `1.2079–1.2815 ms` 降至 `0.0001 ms`；仅切换视图快 `66.3–69.0%`，仅切换搜索快 `56.7–60.7%`，每次真实改变收藏计数仍快 `5.6–10.7%`。
- 同机 5000 条、100 分类的两次反向交错复跑中，稳定分类选择器刷新降至 `0.0002 ms`（快逾 `99.9%`），稳定编辑器刷新快约 `99.1%`，真实 Note 切换快 `83.0–85.6%`，搜索切换快 `18.0–26.2%`；真实分类重排仍快 `2.6–4.4%`。
- 同机两次反向大样本中，0/1/100 分类首次构建与布局分别快 `64.3–67.4%`、`49.4–56.6%`、`91.6–92.6%`；100 个分类由预建 100 个显式 `ListBoxItem` 改为保留 100 个数据项、仅实现视口附近 9–10 个容器。5000 Note/100 分类真实窗口构建另快 `67.2–75.8%`，稳定、选择、计数、单项重排和单项增删刷新均保持正收益。
- Note 菜单复用的最终两次反向实窗复测中，5000 条、0/1/100 分类构建耗时分别为持平至快 `3.7%`、快 `3.0–6.0%`、快 `20.7–26.2%`，线程分配分别减少 `9.0%`、`5.7%`、`21.8%`；7 条/100 分类阈值快 `34.1–42.6%`、分配少 `34.9%`，空、1 条与 6 条直接路径保持与基线完全相同的分配。
- 三个独立进程的真实 `ClearTrash()` 基准中，0 条及 5000/25000 条、0%/1%/50%/100% 删除的九个场景全部正向；最差的 25000 条交错半删路径由 `262.9163 ms` 降至 `0.2439 ms`（快约 `99.91%`），线程分配由 `263480 B` 降至 `944 B`。

## 1.7.0 — 2026-08-23

### Changed

- 将桌面端收敛为更适合人和智能体共同工作的三栏工作台：搜索显示图标、范围提示与 `Ctrl+F` 徽标，标题旁持续显示本地保存真相，底部交接区保留唯一实心主操作“复制正文”。
- 统一按钮、输入框、列表行、滚动条与组合框的 WPF 语义模板，新增工具栏、导航和危险动作角色；悬停、按下、焦点与选中状态不再改变控件几何。
- 系统导航与自定义分类显示实时数量，长分类名不再触发横向滚动；收藏采用金色状态，删除/恢复继续与高频动作隔离。
- 细化紧凑、标准、宽屏和超宽四档三栏宽度，在最小、默认、1080p、1200p、2K 与 4K 工作区保持编辑画布和底部交接动作可达。

### Verified

- 六组自动化测试全部通过；真实 WPF 渲染覆盖六档尺寸、活动/回收站/空状态和石墨、午夜、Win11 雾白、鼠尾草四主题。
- 可见窗口检查确认 `Ctrl+N` 创建并聚焦标题、设置窗口与 UI Automation 名称/说明可用；发布仍为零第三方 DLL、零网络与同目录便携数据。

## 1.6.1 — 2026-08-23

### Changed

- 顶部命令栏只保留分类、收藏和置顶小窗；`Ctrl+Enter`、变量填写、复制反馈及回收站中的可用性边界保持不变。
- 底部复制按钮采用紧凑内边距，在 `860×540` 最小窗口、默认、2K 和回收站布局中保持可达，删除/恢复区继续独立位于右侧。

## 1.6.0 — 2026-08-22

### Added

- 新增零依赖 `SeerNote.Cli.exe`，提供 `schema`、`categories`、`list`、`get`、`create`、`update`、`delete` 和 `restore` 命令。
- CLI 成功时向 stdout 输出单个 `seernote.cli.v1` JSON 对象，失败时向 stderr 输出结构化错误；退出码区分用法、未找到、工作区占用、校验和存储失败。
- 新增 `seernote.note.v1` 结构化 Note 契约，统一桌面“复制为 JSON”和 CLI 的字段、UUID 与 UTC 时间戳格式。
- 桌面编辑区底部新增“智能体交接”组，可复制 Note ID 或 JSON；右键菜单同步提供，回收站 Note 仍可使用。

### Changed

- 删除、还原与永久删除继续独立位于底部右侧，与左侧智能体交接操作分区；顶部“复制正文”和 `Ctrl+Enter` 保持不变。
- 所有 CLI 数据命令与桌面端共享 `data/.seernote.lock`；读取也先加锁，以覆盖启动恢复可能产生的写入。
- 发布结构扩展为同目录的 `SeerNote.exe` 与 `SeerNote.Cli.exe`，仍不引入第三方 DLL、安装器、网络或遥测。

### Safety

- CLI `delete` 只移入回收站，不提供永久删除命令；恢复路径仍由现有原子 JSON、备份和校验实现负责。

## 1.5.0 — 2026-08-21

### Added

- 主窗口新增工作区感知的首次启动尺寸，在 1080p、1200p、2560×1440 和 3840×2160 可用工作区间按比例增长，并限制在 `1080×720` 至 `1920×1280` DIPs。

### Changed

- Per-Monitor V2 继续负责 100%–200% DPI 像素映射；布局以逻辑 DIPs 判断，不按物理分辨率重复放大字体或控件。
- 已保存的有效用户窗口边界继续优先恢复；自适应默认值不会覆盖用户手动选择的窗口大小。

## 1.4.0 — 2026-08-18

### Changed

- 右侧编辑区吸收 Windows 11 记事本的层级与密度：标题成为当前 Note 标签，分类、收藏、复制和置顶小窗进入紧凑命令栏，正文改为大面积无边框纯文本画布。

- 原“雾白”主题调整为“Win11 雾白”，使用浅灰蓝外壳、白色编辑纸面和轻边框；主题总数仍为四个，没有增加皮肤、富文本、账户或伪标签页功能。

- 界面、Note 正文与置顶小窗测量统一使用应用私有的思源黑体 CN Regular，改善简体中文、英文和数字混排时的字形与换行一致性。
- 字体与 OFL 许可证随 `fonts/` 目录发布，不安装到 Windows；字体缺失或损坏时回退系统字体并显示可恢复状态。

## 1.3.0 — 2026-08-18
