# SeerNote 产品规格

## 1. 产品定义

SeerNote 是一个只服务单个本地用户的 Windows 11 便携 Note 工具。它把“临时记下”和“以后快速复用”放在同一窗口中，但不演变成知识库、团队协作平台或 Markdown 工作站。

一句话任务：**随时唤起，立即写下或找到一段文字，然后继续原来的工作。**

## 2. 用户与环境

- 用户：熟悉 Windows 键盘操作、经常使用中文提示词的单个本机用户，以及受该用户控制的本地智能体工作流。
- 设备：Windows 11 桌面或笔记本，键盘和鼠标为主要输入。
- 网络：不需要，也不允许成为核心行为的前置条件。
- 数据：几千条以内的纯文本 Note。
- 发布：一个可复制目录；根目录的 `SeerNote.exe` 直接启动，`SeerNote.Cli.exe` 提供机器接口。

## 3. 顶层工作流

1. 按 `Ctrl+Shift+Space` 唤起并聚焦搜索框。
2. 输入中文或英文，结果随输入更新。
3. 没有结果时按 `Ctrl+N`，查询文字直接成为新 Note 的标题。
4. 选中条目后在右侧立即编辑；停顿约 350 ms 自动保存。
5. Note 按 `Ctrl+Enter` 复制；包含 `{{变量}}` 时先填写再复制。
6. 需要交给智能体继续处理时，复制稳定的 Note ID 或 `seernote.note.v1` JSON；回收站内容也保留这两种检查入口。
7. 本地智能体可调用 `SeerNote.Cli.exe schema` 发现契约，再用列表、读取、创建、更新、软删除和还原命令完成可审计操作。
8. 需要持续显示时，把条目打开为独立置顶小窗；小窗按内容在 `320×180` 至 `720×640` 范围内自适应，超限后纵向滚动。
9. 删除先进入回收站，可逐条还原或永久删除，也可一键清空整个回收站；所有永久删除都需要确认。
10. 设置中可选择关闭主窗口时“彻底退出”或“最小化到托盘”，默认彻底退出；彻底退出遇到保存失败时先提供重试、放弃或取消。
11. 设置中可选择石墨、午夜、Win11 雾白或鼠尾草主题；保存后立即生效并随便携数据迁移。

## 4. 信息结构

主窗口固定为三个区域：

- 左侧：收藏置顶、所有条目、自定义分类和回收站；分类可创建、重命名、删除和拖拽排序。
- 中间：统一的新建入口、带搜索图标/范围提示/`Ctrl+F` 徽标的即时搜索与 Note 结果；Note 可右键操作并拖到左侧分类中移动。
- 右侧：当前 Note 标题标签、可见的本地保存状态、分类/收藏/置顶小窗命令栏、大面积纯文本画布，以及底部左侧集中正文/ID/JSON 复制的智能体交接区和右侧独立的删除/恢复区。

左侧品牌区在应用图标下方显示当前程序版本号，便于确认正在运行的便携副本。系统导航与每个自定义分类都显示实时数量；长分类名省略显示，不产生横向滚动条。

首次启动按当前可用工作区选择约 68% 宽、75% 高的窗口，限制在 `1080×720` 至 `1920×1280` DIPs；最小仍支持 `860×540`。已保存的有效窗口边界优先保留，用户缩放时三栏按内容宽度切换紧凑、标准、宽屏和超宽布局。新建为次级动作，“复制正文”是活动 Note 唯一的实心强调操作；收藏使用金色状态，危险操作保持独立且不与高频命令竞争。

## 5. 功能范围

### 必须交付

- 新建、编辑、自动保存、软删除、还原、单条永久删除和回收站一键清空。
- 统一 Note 与可持久化排序的单层自定义分类。
- 标题、正文和分类的即时中文子串搜索。
- `{{变量}}` 自动识别、填写与复制确认。
- 全局唤起、系统托盘、单实例，以及可持久化的关闭按钮行为。
- 可编辑的独立置顶小窗，位置持久化；打开及正文编辑时按内容自适应尺寸，当前会话手动调整后优先尊重用户尺寸。
- 根目录运行、数据随目录、无注册表产品设置。
- 原子保存、最近备份、损坏文件恢复和明确错误状态。
- 四种克制的深浅中文主题，其中 Win11 雾白吸收 Windows 11 记事本的浅色层级与编辑画布；保留可见焦点、标准文本控件和 DPI 缩放。
- 主窗口适配 1080p、1200p、2560×1440 与 3840×2160 工作区；Per-Monitor V2 使用逻辑 DIPs，避免把高 DPI 像素数误当作字体放大依据。
- 右键菜单、任意层级子菜单和托盘菜单使用一致的语义配色与交互状态；高对比模式服从 Windows。
- 单独的智能体 CLI；机器命令成功时 stdout 只写一个 `seernote.cli.v1` JSON 对象，失败时 stderr 写结构化错误，并使用稳定退出码。
- CLI 与桌面端共享同一原子存储和排它锁；`delete` 只进入回收站，CLI 不提供永久删除。

### 明确非目标

- 云同步、账号、团队库、在线分享、遥测和自动更新。
- 富文本、Markdown 预览、附件、图片、画布、双向链接和插件。
- 脚本执行、提示词市场、AI 调用、剪贴板历史和自动模拟粘贴。
- CLI 永久删除、绕过工作区锁、批量执行 Note 正文或隐式创建分类。
- 定时通知、复杂待办、嵌套文件夹和跨平台支持。
- 密码库或端到端加密承诺。

## 6. Grill 自问自答决策记录

以下问题按依赖顺序逐个解决。用户已明确要求由 Agent 自问自答，因此每项采用推荐答案，不再等待逐题确认。

### Q01：SeerNote 首先解决“记录”还是“管理”？

**推荐答案：记录与取回，管理居后。** 首屏必须允许直接输入和搜索；分类不能成为新建前置步骤。

### Q02：是否建立 Obsidian 式工作区或 Vault？

**推荐答案：不建立。** 只有一个便携目录和一个内容集合，避免路径选择、索引和迁移心智负担。

### Q03：随手记与提示词是两个数据库吗？

**最终答案：没有两种类型。** 所有内容都是统一 Note；`{{变量}}` 是正文能力，不再作为类型或导航分支。

### Q04：标题是否必须手填？

**推荐答案：不强制。** 空标题时从正文第一条非空行生成显示标题；用户仍可独立修改标题。

### Q05：是否支持任意层级文件夹？

**推荐答案：不支持。** 只提供可创建、重命名、删除和拖拽排序的单层分类，防止导航树变成第二个知识库。

### Q06：是否需要标签？

**推荐答案：首版不需要。** 自定义分类和全文搜索已经覆盖目标规模，标签会增加编辑和筛选界面。

### Q07：搜索采用分词还是子串？

**推荐答案：确定性的 Unicode 子串搜索。** 对几千条数据更快、更可预测，也不引入中文分词依赖。

### Q08：无搜索结果时 Enter 做什么？

**推荐答案：不隐式创建。** 显示“以当前文字新建”的明确动作，`Ctrl+N` 执行，避免误建大量空条目。

### Q09：是否自动保存？

**推荐答案：是。** 编辑停顿约 350 ms 后原子保存；状态明确显示“保存中 / 已保存 / 保存失败”。

### Q10：关闭时是否每次询问保存？

**推荐答案：正常情况不询问。** 只有最近一次写入失败且内存内容更新时才阻止关闭并给出重试/导出/放弃。

### Q11：崩溃后如何恢复？

**推荐答案：验证主文件，再按 `.bak`、有效 `.tmp`、历史备份顺序恢复。** 永远保留损坏原件，不静默覆盖。

### Q12：为什么不用 SQLite？

**推荐答案：首版数据小且目标是零依赖单 EXE。** SQLite 事务更强，但会引入托管/原生 DLL；正确实现 `Flush(true)+ReplaceFile` 与备份后，完整状态 JSON 能满足单实例数据规模。

### Q13：为什么不用每条一个 Markdown 文件？

**推荐答案：避免文件名冲突、批量状态一致性和大量小文件。** 提供可读 JSON 导出即可保留可迁移性。

### Q14：程序能否并行启动两个实例？

**推荐答案：不能。** 第二个实例激活第一个窗口后退出，避免同一权威文件的竞争写入。

### Q15：全局快捷键冲突怎么办？

**推荐答案：启动继续但明确提示。** 托盘仍可打开；不因为热键注册失败导致程序不可用。

### Q16：是否自动模拟粘贴到前一个窗口？

**推荐答案：不模拟。** 复制并返回即可；`SendInput` 容易误投递到错误窗口，也会扩大安全和兼容性表面。

### Q17：Note 变量占位采用什么语法？

**推荐答案：`{{中文名称}}`。** 语法直观、可读；重复变量统一填写，空名称按普通文本处理。

### Q18：变量值是否持久化？

**推荐答案：默认不持久化。** 防止上次客户名或敏感上下文被误复用；用户要固定内容应直接写入 Note 正文。

### Q19：复制成功如何反馈？

**推荐答案：状态栏显示“已复制：标题”。** 不只闪颜色，也不弹阻塞对话框。

### Q20：置顶条目和置顶窗口是否相同？

**推荐答案：严格区分。** “置顶”改变列表排序；“置顶小窗”创建独立窗口，避免同一开关含义不清。

### Q21：置顶小窗能开几个？

**推荐答案：允许多个，但一个条目最多一个。** 再次打开时激活已有窗口；关闭不删除条目。

### Q22：首版是否做提醒通知？

**推荐答案：不做。** 可靠提醒需要后台调度、休眠恢复和通知权限；不应以不可靠实现冒充完成。

### Q23：是否提供浅色主题？

**推荐答案：首版先完成单一深色主题；`1.1.0` 在明确需求后增加石墨、午夜、雾白和鼠尾草四种主题，`1.4.0` 将雾白收敛为 Win11 记事本式浅色层级。** 四者共享语义 token 和控件结构，不扩张为皮肤市场；系统高对比模式仍优先使用 Windows 系统颜色。

### Q24：界面怎样避免“通用 AI 面板”感？

**推荐答案：用“可复用文字架”作为签名。** 收藏、分类和 Note 列表形成稳定取回路径，变量复制动作紧邻正文；不使用渐变、玻璃、指标卡和装饰图表。

### Q25：是否自绘文本编辑器？

**推荐答案：不自绘。** 使用标准 WPF 文本控件，优先保证中文 IME、选择、撤销、键盘和辅助技术。

### Q26：最小窗口是否追求手机式窄宽？

**推荐答案：不追求。** 这是桌面三栏工具，`860×540` 是明确下限；置顶小窗负责更小的持续显示场景。

### Q27：是否写注册表保存设置？

**推荐答案：不写。** 所有设置进入 `data/notes.json`，保持目录可移除和可迁移。

### Q28：是否提供导入导出？

**推荐答案：首版提供完整 JSON 导出和单条纯文本复制，不做复杂导入向导。** 权威目录本身已经可备份；导入留给后续明确需求。

### Q29：是否加网络更新检查或崩溃上报？

**推荐答案：不加。** 程序不包含网络调用，隐私与可预测性优先。

### Q30：什么状态才算首版完成？

**推荐答案：固定验收矩阵全部通过且真实渲染完成。** 可选的 Markdown、提醒、标签、跨设备同步不影响关闭当前目标。

## 7. 视觉合同

- 视觉命题：四主题共享清晰的三栏取回路径与单一青绿色动作色；Win11 雾白用浅灰蓝外壳承托白色正文画布，深色主题保持低眩光层级。
- 密度：紧凑但不拥挤，默认一屏可见约 8–12 个条目。
- 形状：6–10 px 小圆角，薄边框，极少阴影；不使用玻璃与渐变。
- 字体：界面与正文统一使用随包的思源黑体 CN Regular，英文、简体中文和数字共享字体度量；无需安装到 Windows，资产异常时才回退系统字体。正文 15–16 px 等效字号。
- 签名元素：收藏星标、有序分类、当前 Note 标签和简化焦点图标共同表达“注视中的文字架”，连接 Seer 名称与可复用 Note。
- 智能体交接：复制正文、稳定 ID 与 JSON 集中位于编辑区底部左侧，正文复制保持唯一强调色与 `Ctrl+Enter`；删除、还原与永久删除保持在右侧，安全语义不因自动化入口而弱化。
- 控件语法：按钮、输入框、列表行、滚动条和组合框由同一语义模板控制；工具栏、导航和危险动作各有明确角色，但仍共享尺寸、圆角、焦点与禁用规则。
- 状态真相：标题旁持续显示“已保存到本地 / 正在保存 / 保存需要处理 / 只读 · 回收站”，让人和辅助技术无需猜测当前写入状态。
- 编辑画布：只迁移参考界面的标签层级、紧凑工具区和大面积正文，不复制富文本、账户、无效标签页或品牌装饰。
- 动效：只允许 120–160 ms 的状态过渡；核心操作不等待动画。
- 焦点：键盘焦点使用高对比青绿色描边；颜色之外同时保留文字或图标状态。
- 稳定性：选中、焦点和点击状态只改变颜色或覆盖层，不改变控件边框厚度、字体粗细或列表结构。
- 响应式：左栏和 Note 列表按内容驱动断点调整，编辑区始终保留最低可用宽度；不按分辨率直接放大字体，也不把三栏简单堆成一列。
- 置顶小窗：以最小占用完整显示正文为优先，在候选宽度中平衡面积与纵横比；达到最大阈值后保持窗口稳定并仅使用纵向滚动。

## 8. 错误与恢复文案

- 空集合：“还没有条目。按 Ctrl+N 写下第一条。”
- 无搜索结果：“没有匹配内容。可用当前文字新建条目。”
- 热键冲突：“全局快捷键已被其他程序占用；仍可从托盘打开 SeerNote。”
- 保存失败：“尚未写入磁盘。内容仍保留在当前窗口；请重试或导出。”
- 恢复成功：“主数据不可读，已从最近有效备份恢复；原文件已保留。”
- 永久删除：“永久删除《标题》？此操作无法撤销。”
- 清空回收站：“确定清空回收站中的全部 N 条内容？此操作无法撤销。”
